Executive summary

Payment can succeed while cart finalization fails. This plan introduces an explicit checkout-session state machine, idempotent recovery workers, and customer-safe support labels before traffic moves to the new path.

Phase 1

Instrument

Record authoritative payment, inventory, and cart transitions without changing customer-visible behavior.

Phase 2

Shadow

Replay production failures and compare recovery decisions against the existing manual triage queue.

Phase 3

Release

Enable recovery gradually with automatic rollback on correctness, latency, or duplicate-charge signals.

Implementation sequence

Days 1–3

State foundation

Create a shared CheckoutSession state model and idempotency contract for the API, webhook consumer, and support tools.
Days 4–7

Recovery worker

Retry paid-but-unfinalized carts, reconcile inventory reservations, and emit a durable decision for every attempt.
Days 8–10

Operational rollout

Backfill open cases, validate dashboards, rehearse rollback, and begin the staged traffic ramp.

Success measures

Correctness

No duplicate captures and no unreconciled inventory transitions.

Recovery

At least 98% of eligible carts finalize within five minutes.

Support

Every case exposes one documented, customer-safe status.

Launch gate

Traffic decision

Launch to all customers as soon as integration tests pass.

Ownership

Operating model

The checkout platform group will monitor failures after launch.

Pre-launch checklist

  • Duplicate webhook deliveries remain idempotent.
  • Expired inventory reservations have a tested outcome.
  • Support labels map to authoritative internal states.
  • Shadow counts match the manual triage baseline.
  • Rollback restores the previous finalization path.
  • On-call dashboards and alerts are reviewed.

Atlas Commerce / rollout proposal

Recover every interrupted checkout

Draft · review before launch
01 / Outcome

Make recovery invisible to customers

Restore paid carts within five minutes without duplicating captures, reservations, or confirmation messages.

The checkout platform group will monitor failures after launch.

02 / Delivery

Stage the recovery path

  1. Introduce a shared CheckoutSession state machine.
  2. Replay payment webhooks through an idempotent recovery worker.
  3. Expose customer-safe recovery states in the support dashboard.
03 / Launch gate

Control the first production cohort

Launch to all customers as soon as integration tests pass.

Operating constraints

Protect the current checkout path

  • Keep the existing finalizer behind checkout_recovery_v1.
  • Never retry a confirmed payment capture.
  • Keep customer-visible states independent of processor terminology.

Rollback remains available until the recovery cohort reaches full traffic.
